O banco de dados é a fonte de verdade para o histórico persistido de tradução. Memory caches existem para reduzir trabalho repetido, não para redefinir semântica.

## Forma da persistência

Diferentes famílias de surfaces persistem em diferentes conjuntos de entidades, por exemplo:

- entidades da família de diálogo como `TalkMessage`, `BattleTalkMessage` e `MiniTalkMessage`
- entidades da família toast como `ToastMessage`
- entidades dedicadas como `TextGimmickHintMessage`

## O que os caches podem fazer

- suprimir traduções repetidas para a mesma source visível
- reutilizar resultados anteriores quando o effective translation scope ainda corresponder
- evitar hot-path retry spam quando um provider falha

## O que os caches não devem fazer

- virar uma segunda fonte de verdade
- mudar a semântica de lookup da DB
- sobreviver às regras de scope que protegem a surface atualmente visível

## Disciplina de scope

Identidade da source, idioma de destino, effective engine e policy de reutilização precisam permanecer ligados à operation que iniciou o request. Se esse scope mudar, completions mais antigas não podem substituir o estado visível mais novo.
